## 2026-09-03 · 初始复盘

### 用户提出的问题

1. 新增记录项选择“和同类数据一起显示”后，进入页面会重复刷新；每日输入使用“别名：具体内容”不能保存，且没有数据时看不到记录项位置。
2. 手机训练记录可以短暂保存多条，但无法在云端稳定接收，并让电脑端保留最近七次完整发送记录。
3. 原始记录疑似无法编辑；编辑后需要保证相关页面、详情、动作历史和云端投影保持一致。
4. 备注应绑定每个动作本身，并可查看；不能只绑定某一次训练中的动作实例。

### 已完成的诊断

- 在隔离匿名沙盒中创建数据模块，并输入 `2026-09-03 诊断心率：58 bpm`，确认数据模块可以保存到独立记录集合，但不会自动成为普通 Body 日期记录。
- 在当时连接的正式服务运行版本中，输入只有 `诊断心率：58` 未进入保存阶段；复核当前工作区源码后确认解析器已经支持无日期别名默认当天，因此该现象属于正式服务运行版本滞后/不一致，不能归因于当前源码规则。
- 当前数据模块历史/导出、普通分类页、普通日期详情使用了不同读取边界。
- 页面重复刷新来自多个增强层和定时刷新任务叠加，不是单纯的浏览器完整刷新。
- 正式服务实际打开普通记录后只有只读详情；当前工作区源码虽存在编辑 API 和编辑表单，但正式服务版本标识与当前工作区不一致。
- 当前动作训练备注主要绑定 `movement_id + 训练历史记录`；动作词典虽有 `notes` 字段，但长期动作备注尚未形成完整的展示语义。
- 已停止诊断用的本地沙盒服务；未修改正式数据、云端数据或产品源码。

### 当前确认的业务理解

“最近七次”采用本地保留模型：

```text
手机每次发送 → 云端负责可靠接收
电脑端读取云端成功 → 写入本地最近记录列表
本地新增第 8 条 → 删除本地时间最远的一条
```

- 云端不负责只保留七条，也不需要因本地清理而删除云端数据。
- 本地保存的是最近七次发送的完整内容，而不是只保存标题、摘要或显示结果。
- 云端读取成功后，本地列表应能在离线时继续查看。
- 同一条发送的重试需要通过稳定发送 ID 去重，不能误增一条。
- “手机发送成功”与“电脑端已经读取并完成本地保存”应显示为两个不同状态。

