# Fitness Ledger 网页反 AI 痕迹审查契约

版本：2026-08-14 / 候选工作树

这不是一套新的视觉系统，也不是把外部 skill 复制进项目。它是 Fitness
Ledger 在已有 `STYLE_BIBLE.md` 之上的审查流程，用来减少重复的 AI 页面
习惯，同时保留当前产品的纸张、档案、身体部位主题和本地优先语气。

## 方法来源与取舍

- `avoid-ai-design` 提供了适合存量页面的做法：先渲染，再按字体、颜色、
  布局、组件、间距、动效、图标和文案逐项审查，区分代码确定和截图推断，
  最后重新审查。
- `Hallmark` 提供了设计前置检查、token 约束、响应式宽度和发出前自我批评
  的思路，但它更适合较重的重设计流程；本项目不整体引入它。
- 社区反例提醒我们："去 AI 味"本身不是验收标准。每一项修改都必须能
  说明它如何更符合本项目的既有证据、数据层级或真实使用任务。

## 每次页面修改的固定顺序

1. 明确页面、用户任务、允许修改的文件和不应改变的行为。
2. 用匿名数据渲染当前页面；至少检查桌面、窄桌面和手机宽度。
3. 记录问题：`P0` 阻断，`P1` 明显干扰，`P2` 轻微重复或装饰问题。
4. 每一条问题标记为 `code-certain` 或 `screenshot-inferred`。
5. 只选择一个方向做小范围修改，优先复用现有 token、素材和页面 recipe。
6. 修改后重新渲染，复查空状态、错误状态、长中文、键盘焦点、减弱动效和
   触摸目标。
7. 审查结果与实现分开记录；没有截图证据时，不把视觉猜测写成事实。

## Fitness Ledger 的具体反模式清单

以下不是禁止使用某个 CSS 属性，而是需要有明确理由才能保留：

- 每个大标题下都自动放一条解释性副标题，尤其是空泛的中文产品宣言。
- 同一页面堆叠多个大小、圆角、阴影都相同的“功能卡片”。
- 已经和正式数据并列的扩展数据，又额外套一个显眼的独立大框或胶囊。
- 用“页面小模块”“高级设置”“下游能力”等内部术语代替用户真正要做的
  选择。
- 通过大面积留白或装饰图把实际记录推离首屏，而不是服务于档案阅读。
- 重复显示同一个值：正式主内容一次、扩展胶囊一次、摘要行再一次。
- 只做漂亮的默认状态，没有空、错误、未配置和只读边界的清楚反馈。
- 文案使用无法核验的“智能、无缝、全方位、快速掌握”等承诺。

## 本项目的保留边界

- `STYLE_BIBLE.md`、正式素材、Body/Diet/Training 的不同记录形态优先级高于
  外部通用 skill。
- 新数据如果选择归入现有类别，应进入该类别现有记录结构；不会因为扩展
  能力而自动生成一套新的页面模板。
- Mini Program 只读，不复制解析器，不新增写入，不因一个扩展模块生成新页。
- 生产目录、正式 tracker、CloudBase 和线上 Mini 发布必须在人工 review 后
  另行授权。

## 交付前自检问题

- 用户一眼能否知道“记录什么、属于哪一类、在哪里看到”？
- 是否删除了重复显示，而不是又增加一个说明框？
- 新模块和其所属类别的主记录是否使用同样的事实层级？
- 只有详情才有的信息，是否确实留在详情而没有挤占摘要？
- 页面是否在没有新增数据、服务未配置和读取失败时仍然诚实可用？
- 是否可以指出每个视觉改动对应的截图证据或现有 Style Bible 规则？
